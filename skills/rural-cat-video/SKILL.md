# 田园猫咪短片导演

把一个手作或做饭选题，做成角色稳定、工序清楚、有猫本能和关系变化的短片。
默认保留真实猫的外形、猫掌和身体比例；田园摄影使用自然侧光、木石竹陶与食物纹理。
用户指定的画风、工具、时长和已有设定优先，已有项目从未完成的一步继续。

## 1. 接住项目与能力

- 读取用户参考、已有脚本、角色图、生成记录和成片；只有文字时，不声称看过参考视频。
- 确定成品、时长、画幅、角色数量、试片范围和预算。非关键空缺先给合理默认。
- 发现并读取当前 Renoise 工具定义，核对账号、可用模型、报价方式、参考模式、任务查询和素材导出能力。
- 角色图优先用用户指定的客户端生图工具；内置生图与本地文件管理不等于离线推理，不推断未返回的模型版本。
- 本地后期检查 Python、ffmpeg、ffprobe；图片字幕方案需要 Pillow，字幕滤镜方案需要对应滤镜和字体。
- 沿用现有授权和预算。只在新增费用超出已授权范围、缺少必要资料或必须改变方案时提问，不每一步重复确认。
- 工具暂不可用时继续完成不依赖它的策划与文件，并明确停在哪个制作环节。

在用户项目目录保存材料，至少包含：

```text
brief.md                 选题、规格、预算与本次范围
characters/              已确认角色母图与身份卡
world.md                 场景、道具、食物状态
shots.md                 文字分镜与步骤字幕
generation/              参数、引用映射、报价和任务状态
clips/                   已下载并验收的原始片段
edit/                    剪辑顺序、字幕与后期参数
exports/                 成片与验收说明
```

## 2. 选题先找猫能演的动作

选有明确成品、可见工序变化、能容纳猫本能的劳动。
把故事写成“刺激物 → 猫动作 → 可见结果 → 搭档回应 → 补救 → 结尾回扣”。
例如圆食材引发拨弄，绳头引发追逐，踩奶用于压面团；不用人类台词解释猫的情绪。
两只猫各有一项本事和一个会添乱的习惯。让认真者也失手，让捣蛋者至少帮成一次。
打闹用短促、收爪的互拍，前后拍清起因和后果；食物特写提供节奏变化。
优先减少同镜复杂接触、腾空翻物、多角色遮挡，不把每个工序都写成事故。

## 3. 固定角色，再固定生活空间

需要新角色或世界观时读 [角色与世界模板](references/character-world.md)。
每只猫独立生成母图：干净背景、可见全身、正常猫掌、稳定体型与毛色；不用多猫拼图当单角色参考。
母图记录眼睛、脸型、体型、花纹、尾纹和少量识别饰物。局部改色时明确保留哪些已确认特征。
左右用猫自身的解剖方向描述，并补充正面观看方向；转头时不随画面左右翻转花纹。
建立小空间：工作台、火源、水源和出入口有固定关系，两猫常用站位可辨。
关键道具记材质、颜色、相对尺寸和位置；食物记数量、形状、颜色和生熟状态。
跨镜变化分“可由剪辑省略”和“必须交代过程”，避免面团突然换色或同一篮子突然变深。

## 4. 写能接起来的分镜

按 [分镜与生成模板](references/shot-generation.md) 写镜号、时长、景别、主体动作、前后状态、字幕和声音。
一镜围绕一个主要动作：从哪里开始、接触在哪里、结果是什么。总时长与交付规格对应。
食物变化用近景，双猫接触用能看清双方的中景；重点镜头给动作留下完成时间。
分镜数量与生成任务数量分开：模型允许时，一段素材可包含数个镜头。

明确三类图片的用途：

- 角色母图锁外观。
- 单镜首帧锁动作开始前的构图，按需生成，不自动扩成全片逐镜生图。
- 生成后抽帧用于验收，不能写成事前分镜图。

若使用首帧，主体应尚未完成动作，猫掌、道具与落点都可见。
先查模型是否允许角色参考与首尾帧混用；普通参考图不能承诺逐像素锁定第一帧。

## 5. 登记素材，拆分生成

沿已授权范围把确认的母图登记到 Renoise，保存角色名、文件名、当前账号素材编号的映射。
任务中实际附上参考素材，注明各素材负责身份、场景还是前段状态；提示词只写编号不等于已附引用。
按当前模型的单段时长、参考数量、音频支持和费用拆段，不照搬过去案例的固定时长或价格。
先用最小可判断样片验证角色与关键互动；已明确要求完整制作时，在授权范围内继续补全。

提交前使本轮方案可核对：

```text
模型与实际返回版本｜画幅｜分辨率｜时长｜音频设置
完整提示词｜引用素材与分工｜本段起始/结束状态
当前报价｜本轮总额｜已授权预算余量
```

提示词按“风格与空间 → 角色引用 → 分时动作 → 声音与限制”组织。
模型支持时使用时间段分镜；不支持时拆为可执行的单镜任务。
准确保存参数、任务编号、费用与返回结果，不给模型未返回的能力或品质背书。
预算按任务编号对账：计入已扣未退费用和仍在生成的预估费用，同一笔只算一次；费用不明先查账，不新增任务。

## 6. 等待、续拍和失败恢复

- 返回任务编号后查询同一任务直到终态；等待超时先查原任务，不另起一单。
- 提交结果不明时，先从任务历史或幂等信息确认是否受理；无法确认时停在这里，避免重复扣费。
- 已成功片段保持不动。续拍描述前段最后可见的站位、物体状态和光线，再引入新工序。
- 视频参考只承担明确的场景或状态参考，避免模型把前段动作重演。
- 先判断瑕疵能否剪辑缓解，再决定局部重做。重试有次数或预算上限，不无限抽卡。
- 新生成使用新的请求标识；同一请求重试是否复用标识，按工具的幂等语义处理。

## 7. 字幕和本地剪辑

下载实际可用片段，保留原文件。按实际切点组接，不机械按文字脚本整数秒拼接。
中文步骤字幕在后期添加；字号、位置和停留时间以手机观看和关键动作可见为准。
可按 [字幕数据示例](assets/captions.example.json) 准备秒制时轴，再运行：

```bash
python3 <skill目录>/scripts/build_srt.py <项目>/captions.json --output <项目>/captions.srt
```

示例时轴只是示范，必须按自己的成片调整。脚本默认拒绝覆盖，确需替换时显式使用 `--force`。
修剪动作未完成、状态冲突或多余尾帧时，检查总时长与后续音画衔接。
保留可用原生声音，听辨配乐、爆音、突变与异常静音；无音乐提示不等于结果没有音乐。
新增配乐、收费剪辑或重生成先核对现有授权，不为包装自动扩大花费。
输出可重跑的片段顺序、路径、切点、字幕和编码参数，不把这些文件称为剪映或 PR 工程。

## 8. 验收与交付

抽看开头、结尾、跨段切点和复杂接触；听实际音轨，用 ffprobe 核对尺寸、帧率、时长和音轨。
最终可播放交付做完整解码检查；字幕检查覆盖每个实际显示区间。
检查角色一致性、半脸左右、猫掌接触、多肢/人手、食物数量与状态、道具尺度、冲突因果和结尾回扣。
问题分“必须修”“剪辑可缓解”“可接受并注明”，给具体时间，不只说整体不错。
交付成片、字幕、角色与分镜、实际提示词与参数、已知费用、剩余瑕疵及项目路径。
区分最终素材、未采用试片、客户端订阅和生图费用，不承诺固定总价或必然爆款。
按已授权位置保存；公开发布、开源或上传其他平台只在相应请求范围内执行。
